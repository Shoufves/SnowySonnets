# SnowySonnets 个人网站需求文档

> 版本：v0.3
> 状态：需求已确认，可进入主题开发
> 技术路线：Hugo 静态站点 + GitHub Pages 托管
> 仓库：https://github.com/Shoufves/SnowySonnets

---

## 1. 项目概述

建设一个个人文章网站，用于存放和管理 txt / md 文章。

网站视觉风格为**黑白灰古典二次元风格**，类似手游《Alter Ego》的氛围：
- 整体低饱和度、以黑白灰为主；
- 古典、文艺、书籍/书柜场景感；
- 二次元人物作为装饰元素融入页面；
- 不追求花哨色彩，重视氛围、构图和留白。

网站定位为个人内容展示站，核心目标是：
1. 方便地新增、修改、删除文章；
2. 文章按类似 Linux 的多级目录结构组织；
3. 用风格化、带过渡动画的界面浏览目录和文章；
4. 提供标签、分类、站内搜索功能；
5. 在电脑（横屏）和手机（竖屏）上都能流畅浏览，不重叠、不溢出、不突兀。

## 2. 技术约束与结论

### 2.1 GitHub Pages 是纯静态托管

GitHub Pages 只能托管 HTML/CSS/JS 等静态文件，不能运行服务器代码、不能连接传统数据库。

本项目确定采用以下方案：

- 使用 **Hugo** 管理 Markdown 文章并生成静态网站；
- 将生成的 `public/` 目录内容部署到 GitHub Pages；
- 内容 CRUD 通过“编辑 Markdown 文件 + 自动构建”完成；
- 目录树由 `content/` 下的文件夹结构自动生成；
- 页面内的“目录滑动 / 文章切换 / 返回”使用前端 JS + CSS 动画实现；
- 每篇文章仍然生成独立的静态 HTML 页面，保证可分享、可被搜索引擎收录，JS 只负责增强交互体验。

### 2.2 登录/注册与评论区

- **传统登录/注册**：不实现，GitHub Pages 无后端，无法安全维护账号体系。
- **评论区**：暂不接入。后续需要时再考虑 Giscus / utterances（使用 GitHub 账号登录评论）。

## 3. 网站基本结构

### 3.1 页面清单

| 页面 | 用途 | 是否必须 |
|---|---|---|
| 首页 / 启动页 | 展示站点名称、简介、入口；使用 start.png | 必须 |
| 文章浏览页 | 目录树 + 文章内容切换的核心页面 | 必须 |
| 标签页 | 按标签聚合文章 | 必须 |
| 分类页 | 按目录结构聚合文章 | 必须 |
| 关于页 | 个人介绍 / 站点说明 | 建议 |
| 搜索页 | 站内搜索 | 必须 |
| 404 页 | 风格化错误提示 | 必须 |

### 3.2 内容目录结构

文章分类直接由 `content/` 下的文件夹层级决定，类似 Linux 目录：

```text
content/
├── _index.md               # 站点首页内容
├── about.md                # 关于页
└── posts/                  # 文章根目录，对应界面中的“/”
    ├── _index.md           # 文章库说明
    ├── linux/
    │   ├── _index.md       # linux 目录说明（可选）
    │   ├── shell/
    │   │   ├── _index.md
    │   │   └── 常用命令.md
    │   └── 系统管理.md
    ├── 随笔/
    │   └── 某篇随笔.md
    └── 未分类/
        └── 第一篇.md
```

规则：
- 文件夹 = 目录，`.md` 文件 = 文章；
- 每个目录下可放一个 `_index.md` 作为该目录的说明/元信息（可选）；
- 界面中的根目录 `/` 对应 `content/posts/`；
- 目录展开状态、文件点击后的内容展示由前端根据 Hugo 生成的页面/数据自动构建。

### 3.3 txt 文件兼容策略

Hugo 对 Markdown（`.md`）支持最好。若希望界面中显示 `.txt` 文件，建议：

1. **优先方案**：将 `.txt` 文章改名为 `.md`。Markdown 是 txt 的超集，纯文本直接改名也能正常显示。
2. **保留 `.txt` 方案**：需要额外验证 Hugo 是否识别 `.txt` 为内容格式；如果不识别，则在构建前用一个转换脚本把 `.txt` 转为 `.md`。
3. 不推荐把文章直接放在 `static/` 里，因为那样 Hugo 不会为它们生成独立文章页，也难以纳入目录树和 Front Matter。

### 3.4 文章 Front Matter 字段

```yaml
---
title: "文章标题"
date: 2025-01-01T12:00:00+08:00
description: "文章摘要"
tags: ["随笔", "Linux"]
categories: ["技术"]
draft: false
# 可选：
# cover: "/img/xxx.png"
# littleEs: "little_Es1"
---
```

## 4. 页面布局与交互（核心）

### 4.1 桌面端整体布局

```text
+------------------------------------------------------------------+
|  [导航栏]                                                        |
|                                                                  |
|  Es_left1  气泡: "今天想要看什么呢？"                 Es_sit     |
|  (左下角)  (尖角指向左下角)                          (右下角)    |
|                                                                  |
|          +---------------------+  +--------------------------+   |
|          | 目录树              |  | 文章内容 / 初始欢迎区     |   |
|          | > Linux             |  |                          |   |
|          |   > shell           |  | 初始：提示“请选择一篇文章”|   |
|          |     - 常用命令.md   |  | 点击文件后：显示正文       |   |
|          | - 随笔              |  |                          |   |
|          +---------------------+  +--------------------------+   |
|                                                                  |
|  背景：background.png                                            |
+------------------------------------------------------------------+
```

要点：
- `start.png` **只用于首页/启动页**，进入文章库后不再使用；
- 文章浏览页使用 `background.png` 作为全站背景；
- 左侧装饰区放置 `Es_left1.png`，其头顶使用 `bubble_frame.png` 气泡，气泡内白色文字“今天想要看什么呢？”；
- 右侧装饰区放置 `Es_sit.png`；
- 中间为工作区：初始时是目录界面；点击文件后目录界面左移，文章内容出现在中右侧；
- 桌面端目录区与文章区同时可见，方便快速切换文章。

### 4.2 首页 / 启动页（start.png）

```text
+--------------------------------------------------+
|                start.png 全屏背景                 |
|  左侧已有人物（画面自带）                          |
|                                                  |
|                     [站点标题]                    |
|                     [一句话简介]                  |
|                     [进入文章库按钮]              |
+--------------------------------------------------+
```

- `start.png` 是横向图片，左侧已经有人物占位；
- **所有首页文字、按钮必须放在右侧区域**，不能遮挡左侧人物；
- 点击“进入文章库”后平滑过渡到文章浏览页。

### 4.3 目录树交互（桌面端）

- 根目录 `/` 显示为“全部文章”或“文章库”；
- **初始状态：所有目录默认折叠**；
- 每个目录行右侧有一个 `>` 图标：
  - 收起状态：`>` 指向右；
  - 展开状态：`>` **顺时针旋转 90°**，变为指向下，并唤出下一级目录和文件；
- **点击目录名与点击 `>` 效果相同**，都可以展开/收起；
- **子目录与子文件相对父级稍微偏右**，体现层级结构；
- 点击文件时，加载并展示该文章；
- 目录展开/收起使用平滑动画，不能生硬跳变。

### 4.4 文章切换交互（桌面端）

1. 初始状态：中间为目录界面，右侧没有文章内容；
2. 用户点击某个文件：
   - 目录面板平滑向左滑动；
   - 文章内容面板从右侧/中间平滑进入；
   - 最终状态：左侧为目录，中右侧为文章正文；
3. 文章界面左下角有“返回”按钮：
   - 点击后文章面板向右滑出；
   - 目录面板平滑回到中间初始位置；
4. 在文章界面中，左侧目录仍然可点击：
   - 点击另一个文件时，直接切换文章内容，不需要先返回；
   - 切换时文章内容淡出/滑出，新内容淡入/滑入，保持目录位置不动。

### 4.5 移动端布局与交互

```text
手机端-目录界面：                手机端-文章界面：
+----------------+              +----------------+
| [面包屑/返回]  |              | [面包屑/返回]  |
|                |              |                |
| > Linux        |              | 文章标题       |
| > 随笔         |              | 正文...        |
| - 某篇.md      |              | 上下滑动浏览   |
|                |              |                |
| little_Es 点缀 |              | little_Es 点缀 |
+----------------+              +----------------+
```

- 手机端**不显示** `Es_left` / `Es_sit` 大型人物，可在空余位置放置 `little_Es1-5` 作为点缀；
- 目录界面：点击目录进入下一级，点击文件打开文章；
- 打开文章时：
  - 当前目录结构整体向左滑动，直到完全移出屏幕；
  - 屏幕只留下文章内容，可上下滚动浏览；
- 返回目录：
  - **手指向右滑动**即可退回到进入文章前的目录层级；
  - 同时提供顶部“返回”按钮和面包屑；
- **返回后停留在进入文章前所在的那一级目录**；
- 面包屑示例：`根目录 / Linux / shell`，可点击跳转到对应层级。

### 4.6 动效与“丝滑”要求

- 所有面板移动使用 `transform` + `opacity`，避免 layout 抖动；
- 推荐动画时长：`300ms ~ 500ms`；
- 推荐缓动曲线：`cubic-bezier(0.22, 1, 0.36, 1)` 或同类“先快后慢”曲线；
- 目录展开/收起、文章进入/退出、移动端目录滑出/滑入都要有过渡；
- 文章内容加载中显示轻量 loading/占位，加载完成后再播放进入动画；
- 如果用户系统开启“减少动态效果”（prefers-reduced-motion），则关闭或大幅缩短动画；
- 移动端必须禁用横向滚动条，避免滑动返回手势与浏览器手势冲突。

## 5. 视觉风格需求

### 5.1 风格关键词

- 黑白灰
- 古典、文艺、书柜、纸张感
- 二次元人物点缀
- 低对比度背景 + 中高对比度文字
- 类似《Alter Ego》的视觉小说/手游氛围

### 5.2 色彩规范（建议）

| 用途 | 色值 |
|---|---|
| 主背景 / 深色 | `#1a1a1a`、`#222` |
| 书柜背景 | 使用 `background.png` |
| 卡片 / 气泡底色 | `rgba(255,255,255,0.85)` 或浅灰 |
| 正文文字 | `#222` 或 `#333` |
| 次要文字 | `#666`、`#888` |
| 分隔线 / 边框 | `#ccc`、`#999` |
| 强调色 | 保持黑白灰，可用深黑或纯白 |
| 气泡底色 | 深灰（已确认），可直接使用白色文字 |

### 5.3 字体

- 使用工作区字体 `font-zyqs06el.ttf`；
- 通过 `@font-face` 引入：
  - 标题、按钮、导航、气泡文字等可使用该字体；
  - 正文建议保留系统字体栈，避免长文阅读疲劳；
- 字体文件约 11 MB，建议后续做**字体子集化 / 转 woff2 / font-display: swap** 优化。

### 5.4 素材使用规划

| 素材文件 | 实际尺寸 | 用途 |
|---|---|---|
| `img/start.png` | 1920×1080 | 仅首页/启动页全屏背景；左侧已有人物，内容只放右侧 |
| `img/background.png` | 1084×814 | 文章浏览页、列表页、详情页通用书柜背景 |
| `img/bubble_frame.png` | 666×375 | 说话气泡框，尖角指向左下角；用于 Es_left1 头顶对话、404 装饰 |
| `img/Es_left1.png` | 600×309 | 桌面端左下角装饰人物，头顶带气泡 |
| `img/Es_left2.png` | 558×447 | 桌面端左下角装饰人物（备用/轮换） |
| `img/Es_left3.png` | 498×280 | 桌面端左下角装饰人物（备用/轮换） |
| `img/Es_sit.png` | 420×595 | 桌面端右下角装饰人物 |
| `img/little_Es1.png` | 162×278 | 小装饰，可用于移动端空位、空状态 |
| `img/little_Es2.png` | 156×284 | 小装饰，可用于移动端空位、空状态 |
| `img/little_Es3.png` | 162×288 | 小装饰，可用于移动端空位、空状态 |
| `img/little_Es4.png` | 164×260 | 小装饰，可用于移动端空位、空状态 |
| `img/little_Es5.png` | 234×222 | 404 页面专用角色 |
| `font-zyqs06el.ttf` | 约 11 MB | 网站标题 / 品牌字体 |

### 5.5 bubble_frame 使用限制

- `bubble_frame.png` 是**说话气泡**，不是文章正文容器；
- 可用于：
  - Es 人物头顶上方，表示说话；
  - 404 页面装饰；
  - 少量卡片/引语；
- **不可作为文章正文容器背景**；
- 文章正文使用简洁的纸张感面板。

## 6. 标签页、分类页、站内搜索方案

### 6.1 分类页（基于目录结构）

分类不额外维护，而是**直接由 `content/posts/` 的目录层级生成**。

- **分类页 `/categories/`**：
  - 展示所有一级目录（即 `content/posts/` 下的第一层文件夹）；
  - 每个分类显示名称、文章数量、简短说明；
  - 点击进入分类详情页。
- **分类详情页 `/categories/linux/`**：
  - 展示该分类下的子分类列表；
  - 同时展示该分类下（包含子目录）的所有文章列表；
  - 点击文章进入正文。
- 层级关系示例：
  - `linux` 是一个分类；
  - `linux/shell` 是 `linux` 的子分类；
  - 一篇文章同时属于其路径上的所有分类，例如 `linux/shell/常用命令.md` 既属于 `linux`，也属于 `linux/shell`。

这样分类页和目录树是同一套数据来源，不会出现“目录里改了，分类页没同步”的问题。

### 6.2 标签页（基于 Front Matter tags）

标签使用文章 Front Matter 中的 `tags` 字段，独立于目录结构。

- **标签页 `/tags/`**：
  - 以标签云或标签列表展示所有标签；
  - 每个标签显示文章数量；
  - 标签大小可随文章数量略微变化，但保持黑白灰风格。
- **标签详情页 `/tags/linux/`**：
  - 展示带有该标签的所有文章列表；
  - 点击文章进入正文。
- 一篇文章可以拥有多个标签；
- 标签不要求预先定义，写文章时在 Front Matter 里加 `tags` 即可。

### 6.3 站内搜索

纯静态站也可以做站内搜索，方案如下：

- Hugo 构建时生成一个 `index.json` 搜索索引；
- 索引内容包含每篇文章的：
  - 标题
  - 链接 URL
  - 日期
  - 摘要 description
  - 标签 tags
  - 分类路径 categories
  - 正文纯文本（可截断或全文）
- 前端提供搜索入口：
  - 导航栏搜索按钮；
  - 点击后弹出搜索框/搜索页；
  - 输入关键字时实时在 `index.json` 中匹配标题、标签、分类、正文；
  - 显示结果列表，点击跳转到对应文章；
- 无需后端、无需第三方服务；
- 文章量不大时，直接在前端过滤即可；文章量很大时可后续引入 Fuse.js 做模糊搜索。

### 6.4 导航栏结构

最终导航栏建议：

```text
[首页] [文章库] [分类] [标签] [搜索] [关于]
```

- “文章库”进入目录树浏览界面；
- “分类”进入 `/categories/`；
- “标签”进入 `/tags/`；
- “搜索”打开站内搜索；
- 移动端收起为汉堡菜单。

## 7. 404 页面设计

### 7.1 内容布局

```text
+-----------------------------------------------+
|                                               |
|          “哎呀……旅人，这是什么地方？”          |
|                                               |
|                little_Es5.png                 |
|                                               |
|    背景区域逐渐出现多个 bubble_frame.png       |
|    （可重叠，大小接近 little_Es5，直到填满）   |
+-----------------------------------------------+
```

### 7.2 交互与动画

- 页面加载后，`little_Es5.png` 和上方文字先出现；
- 周围空白区域中的 `bubble_frame.png` **一个一个地出现**，而不是同时全部出现；
- 每个气泡出现时带淡入/轻微缩放动画；
- **气泡之间可以重叠**；
- 气泡大小与 `little_Es5.png` 差不多（约 234×222 量级），允许轻微波动；
- 气泡数量上限：**30 个左右**；
- 气泡生成直到**基本填满屏幕**后停止；
- **气泡不能覆盖 `little_Es5.png` 和文字**：
  - 气泡属于背景装饰层；
  - 角色和文字属于前景层，z-index 高于气泡层；
- 提供“返回首页”按钮。

## 8. 响应式与兼容性需求

1. `<head>` 中必须包含 viewport meta：
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1.0">
   ```
2. 所有页面在以下宽度下无横向滚动条、无内容重叠：
   - 360px / 390px（手机）
   - 768px（平板）
   - 1280px / 1920px（桌面）
3. 装饰素材不得遮挡正文、按钮、导航等可交互内容；
4. 点击区域在移动端不小于 44×44px；
5. 图片加载失败时显示 alt 或优雅占位；
6. 支持现代浏览器最新两个大版本；
7. 移动端手势操作需避免与页面滚动冲突。

## 9. 功能需求

### 9.1 文章管理（CRUD）

- 新增：新建 Markdown 文件放入对应目录，自动出现在目录树中；
- 修改：直接编辑 Markdown 后重新构建；
- 删除：删除 Markdown 文件后重新构建；
- 移动：移动 Markdown 文件到其他目录，即改变文章分类；
- 草稿：`draft: true` 的文章本地可见，构建时不发布；
- 建议配置 GitHub Actions：
  - push 到 `main` 分支后自动运行 `hugo`；
  - 将 `public/` 发布到 GitHub Pages。

### 9.2 文章浏览与目录树

- 目录树由 `content/posts/` 下文件夹结构自动生成；
- 支持任意多级目录；
- 默认全部折叠；
- 点击目录名或 `>` 均可展开/收起；
- 子目录/子文件相对父级缩进；
- 支持点击文件查看正文；
- 桌面端支持目录与文章同屏；
- 移动端支持“目录 → 文章 → 右滑返回”的完整流程；
- 每篇文章有独立 URL，例如 `/posts/linux/shell/常用命令/`。

### 9.3 分类与标签

- 分类页由目录结构自动生成；
- 标签页由 Front Matter `tags` 自动生成；
- 分类、标签详情页都展示对应文章列表。

### 9.4 站内搜索

- 构建时生成 `index.json`；
- 前端实时搜索标题、标签、分类、正文；
- 搜索结果点击跳转到文章页。

### 9.5 文章展示

- 正文渲染 Markdown：标题、列表、代码块、图片、引用、表格等；
- 显示标题、发布日期、标签；
- 支持上一篇/下一篇（可选）；
- 可选：目录 TOC、阅读时间、字数统计。

### 9.6 其他

- RSS / Atom 订阅（Hugo 自带，保留）；
- 404 风格化页面；
- 暂不接入评论区。

## 10. 性能与 SEO 需求

- 图片尽量压缩，`start.png` 等大图使用懒加载；
- 字体文件优化后加载，避免阻塞首屏；
- 使用语义化 HTML：`header`、`nav`、`main`、`article`、`footer`；
- 每个页面有 `title`、`description`；
- 每篇文章保留独立 HTML 页面，方便分享和 SEO；
- 生成 `sitemap.xml` 和 `robots.txt`（Hugo 默认支持）；
- 动画尽量使用 `transform` / `opacity`，减少重排。

## 12. 已确认决策汇总

1. `start.png` 只用于首页/启动页，进入文章库后不再使用；
2. 目录树默认全部折叠；
3. 点击目录名与点击 `>` 效果相同；
4. 子目录/子文件相对父级缩进，体现层级；
5. 手机端返回目录后，停留在进入文章前的目录层级；
6. 手机端需要面包屑：`根目录 / Linux / shell`；
7. `bubble_frame.png` 是说话气泡，不作为文章正文容器背景；
8. 气泡底色为深灰，文字可直接使用白色；
9. 404 气泡数量上限 30 个左右，可重叠，大小与 little_Es5 相近，基本填满屏幕后停止；
10. 需要标签页、分类页、站内搜索；暂不需要评论区；
11. 仓库为 `Shoufves/SnowySonnets`，部署到 `/SnowySonnets/` 子路径。
